# VLauncher

Windows-лаунчер модифицированного Valheim: React/Neutralino, отдельное Node.js-расширение для установки и запуска игры. Расширение устанавливает обычные файлы: установленный модпак остаётся работоспособным после закрытия лаунчера.

## Разработка и проверка

Нужны Windows x64 и Node.js 22.13+ (для инструментов сборки рекомендуется актуальная Node.js 22 LTS). Команды ниже — для **cmd.exe**.

```bat
cd vite-src
npm ci
npm run check
```

Адреса и ключ берутся из профилей `vite-src/.env.dev` и `vite-src/.env.prod` (они в Git, секретов в них нет). `.env` по образцу `.env.example` нужен только для `npm run dev` и сборки без профиля.

`check` проверяет TypeScript интерфейса, расширения и тестов, ESLint и тесты с контролем покрытия. HTML-отчёт: `vite-src/coverage/index.html`. `npm test` запускает тесты без отчёта; `npm run test:watch` — режим наблюдения. Все упаковщики объявлены в зависимостях; `package-lock.json` хранится в Git. Для разработки из корня проекта: `node vite-src/node_modules/@neutralinojs/neu/bin/neu.js run`.

Полная сборка из корня проекта, по профилю:

```bat
node vite-src/node_modules/@neutralinojs/neu/bin/neu.js update
npm run build:app:dev
npm run build:app:prod
```

| Профиль | Настройки | Результат | Что умеет |
|---|---|---|---|
| `dev` | `vite-src/.env.dev` | `dist/VLauncher-dev` | Админская сборка: панель kuberheim через SSH-туннель (`scripts/start-launcher.mjs`), меню серверов, тестовые серверы |
| `prod` | `vite-src/.env.prod` | `dist/VLauncher-prod`, `dist/VLauncher-prod.zip` | Сборка для игроков: только основной сервер, без туннеля, манифест, архивы и статус серверов из публичного бакета по HTTPS |

**Самообновление прод-сборки.** Сборка вшивает версию (`<дата.время>-<коммит>`, `-dirty` при незакоммиченных исходниках) и пишет её в `dist/VLauncher-prod.json`. Публикует zip панель kuberheim: в её репозитории `node scripts/publish-launcher.mjs --build` (соберёт и выложит) или MCP `bucket` с `action: launcher`; перед публикацией исходники лаунчера закоммичены, иначе версия получит `-dirty`: бакет получает `files/launcher/VLauncher-<версия>.zip` и подписанный тем же ключом, что и манифест, `files/launcher/launcher.json`. Лаунчер при старте и раз в 30 минут сверяет версию, скачивает и проверяет новую сборку в `%LOCALAPPDATA%\VLauncher\launcher-update`, показывает кнопку «Обновить лаунчер»; по ней новый `extension.exe --apply-update` ждёт выхода старого лаунчера, подменяет три файла (при сбое возвращает старые) и запускает лаунчер. Админская сборка не обновляется сама.

`npm run build:app` — то же, что `build:app:dev`. Профиль задаёт `VITE_PROFILE`, `VITE_API_URL` и `VITE_SERVER_PICKER`; переменные окружения оболочки скрипт сборки отбрасывает, чтобы адрес профиля не подменился. Прод-сборка без адреса бакета или с HTTP не собирается. Расширение прод-сборки само отбрасывает из списка всё, кроме `main`, и отказывает в установке и запуске для другого сервера. Индикатор «Файл-сервер» показывает итог опроса `files/servers.json`, отдельного `/ping` у источника не требуется.

Бакет повторяет пути панели: `files/servers.json`, `files/launcher-manifest.json`, `files/releases/<id>/*.zip`, а `VITE_API_URL` указывает на его корень (например `https://s3.twcstorage.ru/<бакет>/`). `neu build` пишет в `dist/VLauncher` (промежуточная папка, её не запускать: открытый оттуда лаунчер блокирует сборку), затем скрипт копирует файлы Windows в папку профиля, не трогая её `.storage`. `neu update` загружает версии нативных бинарников из `neutralino.config.json` (нужен только при отсутствии/смене бинарников). Упаковка расширения использует Node.js 22 x64. Исходный `.env` в бинарник не включается; встраивается только публичный URL обновлений. Не помещайте секреты в `VITE_*`: эти значения доступны клиенту.

Проверить именно упакованное расширение:

```bat
cd vite-src
set VLAUNCHER_TEST_PACKAGED=../extensions/extension.exe
npm test -- tests/runtime.test.ts
set VLAUNCHER_TEST_PACKAGED=
```

Это запускает расширение с тестовым WebSocket-сервером и временным профилем, проверяет протокол, одиночный экземпляр, отсутствие токенов в выводе и корректный выход. Настоящую игру тест не запускает.

## Откуда берётся модпак

Модпак публикует панель kuberheim (репозиторий kuberheim, `docs/PANEL-NOTES.md`). Админская сборка читает её через туннель, сборка для игроков — публичный бакет S3, который панель наполняет сама при выкатке на основной сервер. Пути одни и те же относительно `VITE_API_URL`:

| Путь | Что |
|---|---|
| `files/servers.json` | Серверы: адрес для `+connect`, состояние (`ready`, `starting`…), релиз. В бакете только основной сервер, с `updatedAt`; список старше 10 минут по часам бакета лаунчер считает «нет данных» |
| `files/launcher-manifest.json` | Релиз основного сервера: `releaseId`, четыре архива с sha256 и размером, в бакете ещё `files` (список файлов) |
| `files/servers/<id>/launcher-manifest.json` | Релиз тестового сервера (только панель) |
| `files/releases/<id>/<архив>.zip` | Неизменяемые архивы релиза |
| `files/releases/<id>/files.json` | Каждый файл релиза: путь в папке игры, sha256, размер (только бакет) |
| `files/objects/<sha256>` | Байты файла, общие для всех релизов (только бакет) |
| `files/launcher/launcher.json` | Текущая сборка лаунчера для самообновления (только бакет) |

В бакете `launcher-manifest.json`, `servers.json` и `launcher.json` подписаны ed25519: поле `signature` от JSON остальных полей. Прод-сборка проверяет подпись ключом `VITE_MANIFEST_KEY` и без неё ничего не ставит; `files.json` защищён sha256 из подписанного манифеста, каждый файл — своим sha256.

**Пофайловое обновление.** Если в манифесте есть `files`, лаунчер сверяет файлы в папке игры по sha256 (хэши запоминаются по размеру и времени изменения в `cache/file-hashes.json`) и качает только недостающие, по 6 сразу. Моды почти не сжимаются, поэтому и первая установка идёт по файлам. Если до установки что-то сорвалось (нет файла, битый список), ставятся архивы, а причина пишется в `launcher.log`. Без `files` (админская сборка) ставятся архивы.

Состав архивов:

| Архив | Содержимое | Куда устанавливается |
|---|---|---|
| `BepInEx.zip` | `BepInEx/core/...`, `winhttp.dll`; при необходимости `doorstop_config.ini`, `.doorstop_version` | Корень игры |
| `patchers.zip` | Файлы патчеров без внешнего каталога `patchers/` | `BepInEx/patchers/` |
| `config.zip` | Конфиги без внешнего каталога `config/` | `BepInEx/config/` |
| `plugins.zip` | Моды без внешнего каталога `plugins/` | `BepInEx/plugins/` |

Лаунчер зеркалит `BepInEx/plugins` и `BepInEx/patchers`: файлы, которых нет в релизе, удаляются. Внутри `BepInEx/config` так же зеркалятся только папки серверных модов: `wackysDatabase`, `EpicLoot`, `ValheimEnchantmentSystem`, `_RelicHeimFiles`, `TherzieTranslations`. Чужой yml в этих папках будет удалён. Кэш `wackysDatabase/Cache` удаляется при смене `releaseId`. Одиночные cfg в корне `BepInEx/config` и папки других модов лаунчер не трогает: там остаются локальные настройки игрока. Для базового ZIP допускаются только перечисленные корневые пути.

URL архивов и списка файлов относятся к тому же origin и каталогу релиза, что и `VITE_API_URL`. HTTPS обязателен; HTTP разрешён только админской сборке для localhost и приватных IPv4-адресов домашней сети. Загрузка обрывается, если сервер не ответил за 120 секунд или данные не приходят минуту подряд; медленная, но идущая загрузка длится сколько нужно.

`scripts/publish-release.mjs` — публикация на отдельный file-server без панели (до kuberheim); для серверов kuberheim не нужен.

**Журналы для разбора жалоб:** `%LOCALAPPDATA%\VLauncher\launcher.log` (почему не скачался список серверов, ошибки установки, переход на архивы, самообновление) и `neutralinojs.log` в папке лаунчера (размеры окна при старте и после подгонки под масштаб экрана).

## Сохранность файлов и восстановление

- Все ZIP и файлы сначала скачиваются и проверяются по размеру/SHA-256, архивы распаковываются в отдельный каталог. Редиректы, небезопасные пути, ссылки внутри ZIP, коллизии регистра и превышение лимитов отклоняются.
- Перед изменением игры создаётся резервная копия затрагиваемых файлов и журнал транзакции в `<Valheim>/.vlauncher/`. Ошибка записи или отмена вызывает откат. После аварийного завершения следующий запуск установки сначала восстанавливает незавершённую транзакцию, ещё до сетевых запросов.
- Удаляются только устаревшие файлы, отмеченные в предыдущем `installed.json` как управляемые лаунчером. Посторонние файлы сохраняются. Файлы с совпадающими путями в новом модпаке заменяются с резервной копией.
- Повторная проверка неизменившегося релиза не создаёт дубликаты резервных копий. Копии изменённых файлов хранятся в `.vlauncher/backup-*`; автоматического удаления истории пока нет. Перед ручной очисткой старых копий убедитесь, что `journal.json` отсутствует и новый релиз работает. Кэш находится в `%LOCALAPPDATA%/VLauncher/cache`.
- Игра не запускается до успешной установки. Обновление/оптимизация запрещены при запущенном `valheim.exe`; операции выполняются последовательно. Проверка процесса не защищает от запуска игры вручную извне ровно в середине установки — на время обновления держите игру закрытой.
- Boot.config сохраняется рядом как `boot.config.vlauncher-backup`. Выключение оптимизации восстанавливает исходный файл; если его изменил Steam или другой инструмент, лаунчер сообщает конфликт и сохраняет обе версии для ручного разбора.

Журнал обеспечивает восстановление после прерывания процесса. Это не гарантия от аппаратного повреждения диска или потери несброшенных файлов при отключении питания.

## Переход со старой версии

Закройте старый лаунчер и игру перед обновлением. Старый лаунчер создавал ссылки в папке игры; новая версия **не удаляет и не разыменовывает неизвестные ссылки автоматически**. Если они остались, ошибка укажет конкретный путь. Проверьте цель ссылки, сохраните нужные файлы и замените её обычной папкой/файлом вручную. Не удаляйте каталоги-цели ссылок. После этого повторите установку.

Лаунчер больше не требует постоянного запуска от администратора. Папка игры должна быть доступна пользователю на запись. Если она защищена Windows, используйте Steam-библиотеку с подходящими правами либо явно запустите лаунчер с повышением прав для установки. Отладочный инспектор отключён; нативные API ограничены используемыми методами.

## Границы автоматической проверки

Набор тестов охватывает архивы, HTTP и кэш, транзакции/откат, публикацию релизов, блокировку экземпляров, поиск Steam-библиотек, Boot.config, контроллер, WebSocket/heartbeat/выход, Redux и интерактивные компоненты. Временные игровые папки и сетевые серверы создаются тестами; пользовательский Valheim не изменяется. Пороги покрытия относятся к функциональной логике из `vitest.config.ts`, а не ко всем строкам репозитория.

Перед распространением остаётся ручной smoke-test на настоящей игре: установка реального модпака, запуск через Steam/Valheim, подключение к серверу, UAC для защищённой библиотеки и повторный запуск после закрытия окна. Прохождение автоматических тестов не подменяет эту проверку.
